# 02. 시나리오 기획 양식

새 시나리오는 아래 양식을 `docs/modules/<모듈>.md`에 채우고 **사용자 확인을 받은 뒤** 구현한다.

```markdown
### <모듈>-<번호>. <시나리오 이름> Agent
- 상태: 기획 | 화면 대기 | 구현 중 | 완료
- 영문 태그: <카드에 들어갈 영문 2~3단어, 예: Stock Transfer Opt.>
- 한 줄 설명: <홈 카드 설명, 60자 내외>

**업무 문제**
- 누가: <역할, 예: 영업 담당자>
- 지금은: <기존 처리 방식 — 어떤 T-code/엑셀을 몇 번>
- 시간: 기존 <약 N시간> → Agent <N분>

**트리거**: <Agent가 먼저 알리는가(배치·이벤트), 사용자가 묻는가>

**대화 흐름 (약 6단계)**
| # | 사용자 / Joule | 오른쪽 결과 패널 |
|---|---|---|
| 0 | (시스템) 연결 안내 + 제안 버튼 | – |
| 1 | 사용자 질문 → Joule 분석 결과 표 | KPI 요약 |
| 2 | 원인 분석 / 근거 | 차트·표 |
| 3 | 대응 옵션 비교 | 옵션 카드 |
| 4 | 실행 확인 (`jConfirm`) | – |
| 5 | 실행 결과 + 증빙 화면 버튼 | 생성된 문서 카드 |

**실행되는 SAP 처리**: <API/BAPI 수준으로, 예: API_SALES_ORDER_SRV로 판매오더 납기 확약 변경>

**증빙 화면**
- 표준 앱: <앱 이름 + 앱 ID 또는 T-code>
- 화면 방식: UI5 Object Page | UI5 List Report | SAP GUI
- 스크린샷: <받음 / 요청 필요> (목록, 상세, 필요한 탭)
- 보여줄 변경점: <예: 일정 라인 확약 수량이 0 → 40으로>

**아키텍처**
- 경로: 사용자 → Joule Work → <MCP 서버> → <API/CDS> → S/4HANA (+ AI Core / HANA Cloud 등)
- 기술 배지: <예: Joule Work, ERP MCP Server, OData API, SAP AI Core>

**마스터 데이터** (`world.md`에 있어야 함): <고객, 자재, 플랜트, 문서번호>

**세계관 연결**: <MM 스토리의 어느 지점과 이어지는가 — 원인/결과>
```

## 좋은 시나리오의 조건
- **실행으로 끝난다** — 조회·분석만 하는 시나리오는 증빙 화면이 없다. 문서 생성·변경이 하나는 있어야 한다.
- **숫자가 맞는다** — 대화의 수량·금액·날짜가 증빙 화면과 정확히 일치해야 한다. 데모에서 가장 먼저 걸리는 부분이다.
- **AI가 하는 일이 분명하다** — 단순 조회가 아니라 예측·분류·우선순위·추천·문서 이해 중 무엇인지 한 문장으로 말할 수 있어야 한다.
- **6단계 안팎** — 단계가 길면 시연이 늘어진다. 사용자가 누르는 버튼 1개 = 1단계.
