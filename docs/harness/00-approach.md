# 00. 전체 접근방식

## 이 데모가 보여주려는 것
"현업 담당자가 몇 시간 걸리던 SAP 업무를, Joule Agent가 대화 몇 번으로 끝내고 **실제 S/4HANA 표준 화면에 결과가 남는다**."

그래서 모든 시나리오는 세 부분으로 구성한다.

```
① 업무 문제(Pain point)   ② Joule 대화 (약 6단계)          ③ 표준 앱 증빙 화면
  "매달 4시간 엑셀 작업"  →   조회 → 분석 → 추천 → 확인 → 실행  →  Fiori / SAP GUI 화면에서
                              (오른쪽 결과 패널에 KPI·표)         생성·변경된 문서를 직접 확인
```

- ②의 마지막 "실행"은 반드시 **문서 생성·변경**으로 끝난다 (PO 납기 변경, PR 생성, STO 생성, 송장 보류 해제 등).
- ③은 그 문서를 **SAP 표준 앱 그대로의 모습**으로 보여준다. 데모의 신뢰도는 여기서 나온다. 화면 재현 규칙은 `03-screen-guide.md`.
- 기존 방식 대비 시간 절감(예: "약 4시간 → 3분")을 시나리오마다 정의한다 (`js/story-sto.js`의 비교 표).

## 하나의 세계관, 하나의 이야기
- 모든 모듈은 같은 회사 **BestRun Korea**와 같은 마스터 데이터(`world.md`)를 쓴다.
- 모듈 간 시나리오가 서로 원인과 결과로 이어지게 설계한다.

```
SD  고객 주문 급증 (A-4315 탑재 완제품)
 └→ PP  생산계획 앞당김 → 생산오더 MO-26-0891 자재 부족 → MRP 예외
     └→ MM  선제 경보 → 내부 재고 이전(STO) → 부족분만 발주 → 송장 처리   ← 현재 구현됨
```

- 모듈별 스토리 모드(현재 MM: "11월 10일 아침, 유압실린더 결품 위기")를 만들고, 나중에 SD→PP→MM을 잇는 통합 스토리를 만든다.
- 그래서 새 시나리오를 기획할 때 "MM 스토리의 어느 지점과 연결되는가"를 항상 적는다 (`02-scenario-template.md`).

## 모듈 확장 구조 (목표)

```
index.html          허브 — MM / SD / PP 모듈 선택 (SD 착수 시 전환)
mm.html             MM 모듈 (현재 index.html의 내용)
sd.html, pp.html    모듈별 진입 파일 — 그 모듈의 에이전트 화면 + 증빙 화면만
css/                공통 스타일 (base · joule · fiori · gui)
js/core/            공통 엔진 — 라우터, DemoPlayer, 터치 가이드, 날짜, 아키텍처 빌더, UI5 헬퍼
js/mm/ js/sd/ js/pp/  모듈별 콘텐츠 — 시나리오 steps, 아키텍처 설정, 스토리, 화면 정의
```

현재 상태와 차이:
- CSS/JS는 이미 파일로 분리됨 (`01-engine.md` 참고).
- **아직 엔진과 MM 콘텐츠가 섞여 있다** — `js/app.js`(엔진 + MM 시나리오 7개), `js/ui5-views.js`(UI5 헬퍼 + MM 화면), `js/story-sto.js`(스토리 엔진 + MM 스토리). SD 첫 시나리오 착수 전에 `js/core/`와 `js/mm/`으로 나누는 것이 선행 작업이다.
- 엔진은 페이지 ID 접두사 `agent`와 요소 ID `aN-…`에 의존한다. 모듈 파일을 나누면 각 모듈 안에서 `agent1`부터 다시 번호를 매기면 된다.

## 작업 순서 (모든 시나리오 공통)
1. **기획** — `02-scenario-template.md` 양식으로 `docs/modules/<모듈>.md`에 시나리오를 적고 사용자 확인을 받는다.
2. **증빙 화면 확보** — 재현할 표준 앱의 스크린샷을 사용자에게 받는다 (목록 + 상세, GUI라면 탭별).
3. **마스터 데이터** — 필요한 고객·자재·문서번호를 `world.md`에 추가한다.
4. **구현** — `01-engine.md`의 "에이전트 추가 체크리스트" 순서대로.
5. **검증** — `04-verification.md`.
6. **기록** — `docs/modules/<모듈>.md`의 상태를 갱신하고 커밋.
